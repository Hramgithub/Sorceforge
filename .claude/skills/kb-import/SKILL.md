# Перенос в базу: приём, план, извлечение (Р-139)

Конвейер — `pipeline/README.md`; правила записи — `docs/conventions.md`; решения — `docs/project-goal.md` §6.
Владелец отвечает по-русски, решения — по одному вопросу с рекомендацией.

## 0. Приём

1. Книга есть в `pipeline/source/books.json`? Нет — найти в `1_Библиотека` (Р-164; сначала каталог владельца
   `3_КБ\_Каталог.csv` — колонка «Библиотека» даёт папку сценария) и записать:
   `python pipeline/source/pages.py register <book_id> "<pdf>" --title "…" [--offset N]`
   (издание — по метке в начале имени файла, `pipeline/source/library.json`; `[RU-ИИ …]` — машинный перевод,
   не источник, отклоняется). Файлы Яндекс.Диска при первом чтении тянутся из облака — долго, в фоне.
2. Текст: `python pipeline/source/pages.py text <book_id>`; страницы: `python pipeline/source/pages.py pagemap <book_id>`
   показывает разницу печатной и физической страницы по номерам на страницах. Одна разница по всей книге —
   записать `offset`; растёт (в скане пропущены страницы) — `pagemap --write` (карта `page_map`). Проверить на 2–3
   страницах (`show`, `image`): номер на изображении = «с. N» в выводе. «Номера найдены на 0 страницах» не значит,
   что номеров нет (в книгах Miskatonic Repository `pagemap` их не видит) — смотреть картинку страницы. Знак
   `offset`: физическая = печатная − offset, т. е. обложка без номера и «с. 3» на физ. 4 — это `offset: -1`.
3. Опись: заголовки нужного диапазона (`show`, `grep`), что уже есть в базе (`Grep` по `kb/`), что
   из этого — новые записи, что — правки существующих.

## 1. План

Папка работы — `checks/<YYYYMMDD>-<тема>/`. В ней `plan.json` по образцу
`pipeline/briefs/examples/pobeg-iz-innsmuta-scenarios.json`:
`book_id`, `goal`, `decision` (Р-NN этой работы), `check_dir`, `models` (готовые записи-образцы),
`extra` (особые правила этой работы: схема id, что считать одной записью), `units` (имя, страницы,
цель, `owns` — какие файлы часть создаёт и правит, `sites`).

- Части не пересекаются по файлам. Общие записи (город, район, чужие сцены) не принадлежат никому —
  их правят через предложения.
- Перед запуском показать владельцу план одной таблицей и дождаться «да», если в плане есть новое
  решение (новая схема id, новый вид записи). Решение — строка Р-NN (навык `kb-decision`).

## 2. Извлечение

1. Задание каждой части: `python pipeline/briefs/make_brief.py <plan.json> <часть>` → `.cache/briefs/…md`.
2. Запустить по помощнику на часть параллельно (Agent; тип `kb-extractor`, если он доступен в сессии,
   иначе `general-purpose`). Промпт: «Прочитай задание `<путь>` и выполни его; в конце — отчёт по
   разделу Report». Задание уже содержит `docs/conventions.md` целиком — правила не пересказывать.
3. Пока помощники работают — короткие статусы владельцу.
4. Дальше — навык `kb-integrate`; картинки книги (портреты, раздатка, карты) — навык `kb-art`; книга правил — навык
   `kb-rules-book`; английская книга — сначала глоссарий (`kb-terms`).
5. Каждую готовую часть — коммит сразу (файлы части называть явно: выбор по страницам источника — `sources[].printed_page`
   в диапазоне части), не дожидаясь соседей.

## 3. Проверка полноты (обязательно, перед выпуском)

Навык `kb-verify`: `python tools/completeness.py --books <id>` (страницы без записей, картинки без записей) и
`python tools/scenario_check.py --books <id>` (целостность сценариев), затем сверка чтением по заданиям
`checks/20261114-scenarios/README.md` и `checks/20261115-content/README.md`.

## Ошибки, которые уже находили (проверять в заданиях и при сведении)

- Сценарий «пропущен как соло» без проверки: соло — только книга-игра с нумерованными абзацами (Р-230); обычный
  сценарий для одного игрока переносится как сценарий.
- Источник записи — все страницы статьи, а не только первая; у сценария первая страница — титул главы, не оглавление.
- Существа — числа и броня по Malleus Monstrorum (Р-22); значение «Книги хранителя», которое заменили, — в `corrections.from`
  как напечатано; «Other names» — в `aliases`; основной текст статьи — `legend`; у божеств — срок возвращения после 0 ПЗ.
- Навыки и правила — полный текст статьи книги, а не пересказ; частные правила внутри статьи не теряются.
- Первоисточник — тот, что назван в решениях (для «Тёмных веков» — перевод, не предварительная английская версия).
- Раздатка и прегены в отдельных PDF папки книги (`Раздатка\`, `Прегены\`) — записать книгой (`register`) и взять текст
  оттуда, а не пересказ.
- Планы и карты книги — записи `map` с метками, не «атмосфера»; схемы улик — картинки записей глав (Р-247).
- Картинки — сразу при переносе, по навыку `kb-art`, включая сканы и мелкие портреты (Р-245).
- Одинаковое `name.ru` у двух записей одного вида — ошибка перевода (дать каждой своё название).
- Английская книга: кроме записей — переведённая версия книги, HTML рядом с оригиналом (Р-251, навык `kb-translate`).

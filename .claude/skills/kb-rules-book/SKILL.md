# Книга правил → база (Р-175, Р-177)

Основа — навык `kb-import` (приём, план, помощники) и `kb-integrate` (сведение). Здесь — что особенного у книги
правил. Образец сделанной работы — `checks/20261108-rules/` (план, покрытие по главам, предложения, сверка с Foundry).

## 1. Понять книгу

1. Приём (`kb-import`, шаг 0): книга в `pipeline/source/books.json`, текстовый слой, карта страниц (`pages.py pagemap`;
   английские книги Chaosium обычно `offset` −1 или 0 — проверить на изображении 2–3 страниц).
2. Оглавление (`pages.py show <book> <стр. оглавления>`) → таблица глав: страницы, о чём глава, **какие виды записей**
   в ней. Типовая раскладка:

   | Что в книге | Куда |
   |---|---|
   | правила, процедуры, необязательные правила, советы Хранителю | `rule` (`kb/rules/`), раздел книги = запись; `optional: true` |
   | таблица с броском (1d10, 1d100…) | `table` (`kb/tables/`), правило ссылается на неё |
   | новые навыки, профессии | `skill`, `occupation` (в книге-источнике — новые записи; изменения ядра — предложениями) |
   | архетипы, таланты, иное, чего нет в схемах | **новый вид записи — решение владельца** (`kb-decision`) до запуска |
   | оружие, снаряжение | `weapon` (снаряжение — когда будет вид записи) |
   | заклинания, книги Мифов, артефакты | `spell`, `tome`, `rule` раздела «артефакты» |
   | существа, NPC, прегены | `creature`, `character` (`kb/books/<book_id>/…`) |
   | сценарии | `scenario`, `scene`, `item`, `handout`, `organization` — отдельной частью, как «Побег из Иннсмута» (Р-133, Р-134) |
   | города, места, карты | `location`, `map`; в уже существующий город — новые места с источником книги (Р-80), метки на карте — только после обсуждения с владельцем |
   | вступление, художественный текст, история хобби | не переносится (сказать в покрытии) |

3. Ось записей: `axes.ruleset` — `core` для ядра, `pulp` для Pulp Cthulhu, `other` для домашних и прочих; `axes.era` —
   эпоха книги. Записи расширения, которые меняют правило ядра, ссылаются на него (`refs`) и говорят, что меняют.
4. Английская книга: русский текст — наш перевод, флаг `translated` (Р-21); термины — по глоссарию и уже переведённым
   записям базы (навыки, характеристики), английское название — в `name.en`.

## 2. План и решения

- Папка `checks/<YYYYMMDD>-<книга>/`, `plan.json` по образцу `checks/20261108-rules/plan.json`: части по главам
  (≈20–40 страниц на помощника), `owns` — «новые файлы в kb/rules/ для этих страниц» и т. п.; в `extra` — правила этой
  работы (одна запись — один раздел, slug по английскому заголовку, таблицы с броском — отдельно, покрытие
  `checks/…/<часть>.md`, ссылки только на существующие записи).
- Владельцу — одна таблица плана (части, что куда, что не переносим) и вопросы о новых видах записей. Без «да» не
  запускать. Решение — строка Р-NN.

## 3. Перенос и сведение

1. Задания: `python pipeline/briefs/make_brief.py <plan.json> <часть>`; помощники `kb-extractor` по 3–4 одновременно,
   в фоне; владельцу — короткие статусы по мере готовности частей.
2. Каждую готовую часть сразу: `python tools/check.py <её файлы>` → коммит (не ждать остальных). Файлы чужих частей,
   которые ещё пишутся, в коммит не брать (называть файлы явно).
3. После всех частей (`kb-integrate`): предложения частей (`apply.py`), ссылки между главами — одним файлом
   предложений `proposals-integration.json` (помощники перечисляют в отчёте, на что не смогли сослаться),
   `python tools/check.py` по всей базе — 0 ошибок.
4. Опечатки книги — `errata` как напечатано; расхождения изданий — `quality.notes`; пропущенные в скане страницы —
   в покрытии.

## 4. Сверка с журналами владельца (если есть)

Журналы Foundry «Правила: …» (`checks/20261107-foundry/`) — отчёт «совпадает / расходится / нет в книге /
упрощено / частично» (`foundry-vs-book.md`); владелец размечает «моё» (домашние правила, `house-rules`, Р-176,
Р-179) или «ошибка» (правку ведёт чат Foundry, Р-172, Р-181).

## 5. Показ

- Вкладка «Правила»: каркас — главы «Книги хранителя» (Р-185); правила расширения (Pulp…) встают в главу правила ядра,
  которое меняют (поэтому у каждого такого правила ссылка на правило ядра в `refs`), иначе — по соответствию глав:
  в `chapters` книги в `pipeline/source/books.json` третье поле — глава «Книги хранителя». Новая книга правил —
  добавить ей `chapters` с этим соответствием.
- Проверка в браузере (`viewer-change`), выпуск (`kb-release`), сайт — по просьбе владельца.

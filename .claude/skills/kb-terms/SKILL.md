# Термины

Глоссарий — записи `term` в `kb/terms/` (спецификация — `schemas/README.md`, «Глоссарий»). Приоритет русского термина:
**официальная локализация** (русское издание) > **реестр владельца** (`C:\_Hobby\_work\CoC-terminology-20261011\terminology\CoC_Terminology_Decisions.csv`,
Hramgithub/CoC) > доверенный фанатский перевод > наш перевод.

## Перед переводом

- `python tools/terms.py <слово>` — ищет по глоссарию и по названиям всех записей (правила, навыки, таланты…):
  принятый перевод, варианты с происхождением, «не писать».
- Принятый (`accepted`) термин писать как есть; `review` — можно, но в отчёте отметить.
- Нового термина нет — наш перевод, английское слово — в `name.en`/`aliases` записи; после переноса — пересборка.

## Пересборка

`python -I pipeline/migrate/terms_build.py "<реестр.csv>"` (сначала `--dry-run`):
- берёт реестр владельца, глоссарий «Книги хранителя» (`checks/20261108-terms/kr-glossary.json`), официальные
  характеристики, названия навыков, профессий, архетипов, талантов из записей;
- перевод, совпадающий слово в слово с официальной записью того же вида, считается официальным; название из
  фанатского перевода — только если английское имя официальной записи не известно как другое (её собственное или
  нашей переведённой записи с тем же русским именем: «Учёный» — Scientist, не Scholar);
- один и тот же наш перевод из двух книг остаётся двумя вариантами; пустой перевод реестра не становится именем;
- глоссарий переставляет слова для алфавита («Удачи проверка») — принят естественный порядок из реестра;
- имена файлов, занятые Windows (`con`, `nul`…), получают `-term`;
- расхождения официального с реестром — `checks/20261108-terms/conflicts.md`: показать владельцу.
Перед пересборкой удалить `kb/terms/` целиком (файлы порождаются заново); затем `python tools/check.py kb/terms`
(правила записи к терминам не применяются — термин цитирует формы) и коммит.

## Новый источник терминов

Официальный глоссарий или указатель другой книги (русское издание) — переписать в JSON по образцу
`kr-glossary.json` ({ru, en, definition, page, physical_page}) и добавить шаг в `terms_build.py`.

Глоссарий книги с готовыми полями записи (официальное издание или надёжный фанатский перевод: `by`, страница, определение,
источники, пометка) — `checks/<работа>/book-terms.json` ({en, ru, by, book_id, page, variant_note, aliases, avoid, domain,
scope, definition, refs, sources, notes, slug?}; шаг 1d, образец — `checks/20261114-ru-more/book-terms.json`, глоссарий
«Тёмных веков»). Записи прямо в `kb/terms/` пересборка стирает: всё новое — только через такие файлы.
Связь существующего термина с записями книги (бывшее предложение `append refs` к `coc:term:*`) — запись без `ru`:
`{en, refs}` в `book-terms.json` работы (образец — `checks/20261111-fsln/book-terms.json`); она не добавляет перевода.
Новый вариант перевода к термину — запись с `ru` и `by` там же (образец — `checks/20261113-ru-rest/book-terms.json`).
Предложения правок к `coc:term:*` не применять к `kb/terms` напрямую — переносить в эти файлы и пересобирать.

Термины, выбранные при переводе английской книги (наш перевод), — `checks/<работа>/new-terms.json`
({en, ru, aliases, avoid, domain, ref, note}; страница и книга берутся из записи `ref`); пересборка подхватывает все такие
файлы сама (образец — `checks/20261111-keepers-companion/new-terms.json`).

## Выгрузка

`python tools/terms.py --export <файл.csv>` — CSV в столбцах реестра владельца (для синхронизации с NRI, Foundry и
веб-помощником); `--review` — сколько ждёт владельца, по областям.

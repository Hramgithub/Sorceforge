# Перевод книги через Codex (эксперимент владельца, 2026-11-26)

Отличие от `kb-translate` — только в том, кто переводит страницы. Записи базы, список терминов, сборка HTML,
проверка и коммит остаются у ведущего (Claude). Codex видит репозиторий и `AGENTS.md`, но не видит этот диалог и
навыки Claude — всё нужное есть в шаблоне `pipeline/translate/codex_prompt.md`.

## 0. Что должно быть готово до Codex

- Книга перенесена в базу (`kb-import`, помощники `kb-extractor`): записи с `name.ru`, отчёт части
  `<check_dir>/<часть>.md` со списком терминов English → русский и опечатками, картинки в `app/art`, `app/maps`,
  атмосфера `<check_dir>/atmosphere*.json`.
- Текстовый слой книги: `python pipeline/source/pages.py text <book>` (Codex читает его через `pages.py show`).

## 1. Задание

Файл `.cache/codex/tasks/<имя>.json` (UTF-8), одна часть книги — одно задание:

```json
{"book": "<book_id>", "tr_dir": "checks/<дата>-<тема>/translation", "pages": "1-40",
 "title_en": "…", "credits": "<издатель>, <год>", "part": "часть 1 из 3: физические страницы 1–40",
 "terms_md": "checks/<дата>-<тема>/<часть>.md", "art_glob": "<префикс картинок>-*",
 "atmo": "checks/<дата>-<тема>/atmosphere.json", "img_prefix": "p1-", "write_meta": true,
 "meta": {"title_ru": "…", "title_en": "…", "book_id": "<book_id>", "authors": "…", "publisher": "…", "year": 2020, "printed_offset": 0}}
```

- Части по ~30–50 страниц; `write_meta: true` — только у первой части; у каждой части свой `img_prefix`.
- Пробный рендер без запуска: `pwsh -NoProfile -File pipeline/translate/codex_translate.ps1 -Task <файл> -DryRun`
  → `.cache/codex/<имя>.prompt.md`.

## 2. Запуск

```powershell
pwsh -NoProfile -File pipeline/translate/codex_translate.ps1 -Task .cache/codex/tasks/<имя>.json
```

- Запускать в фоне (`run_in_background`), части — параллельно, до 6 сразу (решение владельца 2026-11-26: параллелить).
  Codex медленный (~3 мин на страницу), зато части не мешают друг другу. Лимит — тарифа ChatGPT владельца (окно Codex);
  из командной строки его не видно: если части начнут падать с ошибкой лимита — остановить запуски и сказать владельцу.
- Части крупнее (30–50 страниц): каждый запуск сначала читает инструкции и образцы (~20 тыс. токенов), на крупных
  частях эта цена меньше на страницу.
- Запуск «лёгкий» — только для нашей работы, общий `~/.codex/config.toml` владельца не трогаем: отключены память из
  других проектов, веб-поиск, MCP-серверы (node_repl стартует до 2 мин), плагины приложения, уведомления. Нужно
  переводчику только оболочка, файлы и просмотр картинок. Лог — JSON-события; в конце скрипт пишет токены Codex и
  ошибки (лимит, неизвестная модель). Новый плагин или MCP в конфиге владельца — добавить в список отключённых.
- Codex работает в репозитории с правом записи только в рабочую папку (`workspace-write`, без вопросов);
  модель по умолчанию — `gpt-6.2-sol` (решение владельца 2026-11-26: с 26.11 по 26.12.2026 все переводы книг — через
  Codex с этой моделью, токены Claude экономим; после — итог эксперимента владельцу), другая — `-Model` (список — `codex debug models` или `~/.codex/models_cache.json`;
  каталог меняется с обновлениями Codex: 2026-11-26 утром аккаунт отказывал gpt-6.1-sol и gpt-5.5, днём отвечали
  gpt-6.2-sol, gpt-6.2-astra, gpt-6.1-sol, gpt-6-sol, gpt-6-luna). При «model is not supported» — проверить список и
  повторить с другой моделью. Уровень рассуждений — из конфига (high), другой — `-Effort`.
- Лог — `.cache/codex/<имя>-<время>.log`, итоговый отчёт Codex — `.cache/codex/<имя>.report.md`; после работы скрипт
  сам запускает проверку.
- Упал или не вошёл в аккаунт — хвост лога; `codex login` выполняет владелец сам.

## 3. Проверка ведущим (Codex — чужая модель: не принимать на слово)

1. `python -I -B pipeline/translate/check_translation.py <tr_dir> <book> --pages <диапазон>` — «ошибок нет»;
   короткие страницы (`<<<`) прочитать против оригинала.
2. Выборочно 3–5 страниц глазами: имена и термины = `name.ru` базы, статблоки, раздатки, примечания переводчика.
3. `git status` — Codex не должен был трогать ничего, кроме `tr_dir` (записи базы, инструменты). Чужие правки —
   откатить и записать в отчёт эксперимента.
4. Свести части: заголовки частей, оглавление, стыки страниц, единые формы бросков.

## 3а. Термины и глоссарий

- До запуска: термины книги уже в глоссарии или в отчёте части (`terms_md`), чтобы Codex взял их, а не придумал свои;
  если отчёт части есть, а `checks/<работа>/new-terms.json` ещё нет — сначала свести его и пересобрать глоссарий
  (навык `kb-terms`), тогда `tools/terms.py` у Codex их найдёт.
- Codex пишет свои новые термины в `<check_dir>/codex-terms-<задание>.json` (с определениями). Ведущий сверяет их с
  `name.ru` записей, частями между собой и с глоссарием, переносит в `checks/<работа>/new-terms.json` и пересобирает
  глоссарий. Термин, где Codex разошёлся с базой, — исправить в переводе, не в базе (база — первоисточник формы).
- Синхронизация с реестром владельца: `python tools/terms.py --export <файл.csv>` — по просьбе владельца.

## 4. Сборка и коммит

- HTML собирает ведущий (библиотека вне песочницы Codex):
  `python pipeline/translate/build_html.py <tr_dir> "<папка оригинала>\[RU-ИИ 7e] <название>.html"`
  (путь к библиотеке — из `pipeline/source/library.json`).
- Коммит `<tr_dir>` как обычно; в сообщении — «translated by Codex».

## 5. Итог эксперимента

После книги — в передаточный документ коротко: время, сколько правок понадобилось, качество против перевода
помощниками Claude (термины, пропуски, стиль), решение владельца — продолжать ли.

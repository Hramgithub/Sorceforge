# Английское произведение: база + переведённая книга (Р-251)

По одному произведению за раз; сначала короткие сценарии.

## 0. Перед началом

- Метка «[EN 7e]» в библиотеке бывает ошибочной: файл — копия «[EN 6e]» (одинаковый хеш; бесплатные вставки
  LaBossiere) или статы вида «STR 12». Такое не берём (7e first), пропуск — в передаточный документ.
- Сценария может не быть в каталоге по-русски, но быть в базе по русскому переводу («The Haunted Clubhouse» =
  «Маленький клуб ужасов»): искать ключевые имена в `kb/books/*-ru/`. Если есть — второй набор не заводится, по Р-147
  оригинал даёт числа и английские `sources`/`name.en` предложениями к записям перевода; HTML не делается.
- Термины проверок: Hard — «трудная проверка» (офиц. «трудный успех»), Extreme — «чрезвычайная» (офиц. «чрезвычайный успех»).

## 1. База

Как обычно — навыки `kb-terms` (глоссарий до перевода), `kb-import`, `kb-art`, `kb-integrate`, `kb-verify`.
Источник записей — английский оригинал; русский текст — наш перевод (флаг `translated`); официальные русские
формы имён и терминов — по глоссарию (Р-184).

## 2. Переведённая версия книги

- Перевод целиком, по страницам, в порядке книги: главы, врезки, таблицы, раздатка, статблоки; картинки книги — на
  своих местах (вырезки из PDF); карты — картинкой. Термины и имена — те же, что в записях базы (сначала база, потом
  книга, или сверка после).
- Перевод пишется по страницам в `checks/<дата>-<тема>/translation/NNN.md` (Markdown; картинки — `![подпись](img/…)`
  из `translation/img/`; раздатка — блок `> **Раздатка …**`; статблок — блок ```` ```stat ````), плюс `meta.json`
  (`title_ru`, `title_en`, `authors`, `publisher`, `year`). Две соседние раздатки разделять строкой `<!-- -->`, иначе Markdown сольёт их в одну рамку. Вложенный список —
  отступ 4 пробела (2 сборщик сливает в плоский). `NNN` — физическая страница PDF; если печатный номер другой, в
  `meta.json` — `printed_offset` (печатная = физическая − он), подвал страниц покажет печатный номер; страницы без печатного номера (обложка, титул, приложения, бонус) —
  списком физических в `unnumbered`, их подвал назовёт страницу PDF. Сборка:
  `python pipeline/translate/build_html.py <папка> <файл>`.
- Порядок работы, проверенный на двух книгах: сначала импорт помощником `kb-extractor` (он же выписывает термины
  English → Russian в `<тема>.md`), потом перевод книги отдельным помощником по этому списку и `name.ru` записей;
  опечатки книги — «*Прим. перев.*», те же, что в `errata` записей.
- Один файл `[RU-ИИ 7e] <русское название>.html` (картинки внутри файла, base64, или папка рядом с тем же именем) —
  в папке оригинала в `1_Библиотека`. Метка `RU-ИИ` — наш машинный перевод: источником базы он не считается (Р-147).
- В начале файла — пометка: перевод выполнен для личного использования, оригинал и автор, дата.
- PDF не делается.

## 3. Готово, когда

- записи прошли `kb-verify` (полнота, сценарий цел);
- глоссарий пополнен: термины работы из отчётов частей (и `codex-terms-*.json`, если переводил Codex) сведены в
  `checks/<работа>/new-terms.json` (`{en, ru, aliases, avoid, domain, ref, note, definition}`, `ru` = `name.ru` записи,
  без терминов, что уже приняты в глоссарии), глоссарий пересобран (навык `kb-terms`, «Пересборка»), расхождения с
  официальными формами — владельцу (с 2026-11-15 по 2026-11-26 этот шаг пропускался — не повторять);
- HTML открывается в браузере, все главы и картинки на месте, имена совпадают с базой;
- коммит базы; HTML — в библиотеке владельца (не в репозитории);
- запись в передаточный документ и в `docs/import-queue.md`.

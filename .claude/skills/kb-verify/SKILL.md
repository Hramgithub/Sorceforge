# Проверка полноты и целостности

Отличие от `kb-check`: та проверяет правила записи; эта — что из книги ничего не потерялось.

## 1. Механика (быстро, без помощников)

- `python -I -B tools/completeness.py [--books <id,…>]` → `checks/<дата>-completeness/`: страницы с текстом, которые
  не цитирует ни одна запись; картинки PDF, которые не несёт ни одна запись (кроме `pipeline/art/atmosphere.json`);
  записи без описания; раздатка без текста и картинки; сцены без места.
- `python -I -B tools/scenario_check.py [--books <id,…>]` → `checks/<дата>-scenarios/`: у каждого сценария — части
  сюжета, сцены без места/участников/итога, персонажи и улики страниц сценария вне его семьи, страницы без записей.
- Ограничения: сканы без текстового слоя не дают ни пробелов текста, ни картинок — их сверять только чтением.

## 2. Сверка чтением (помощники)

- Сценарии — задание `checks/20261114-scenarios/README.md`; остальное (правила, списки, существа, путеводители) —
  `checks/20261115-content/README.md`. Части — по книгам, не больше 6 помощников одновременно; каждый пишет
  `<часть>.md` с вердиктом и таблицей потерь (важность высокая / средняя / низкая).
- Длинные списки книги (заклинания, существа, профессии, оружие, места путеводителя) — сверять скриптом целиком
  (названия из текста против `name`/`aliases`), числа — по каждой странице скриптом и выборочно глазами.
- Итог — `summary.md` (таблица «что исправить» по частям) и вопросы владельцу по одному.

## 3. Исправление

- Задание исправлений — `checks/20261115-content/FIX.md` (образец): часть = строка итоговой таблицы, у каждой — свой
  круг файлов; изменённые значения — в `corrections`; картинки — предложениями, их применяет ведущий.
- Ведущий коммитит каждую часть сразу и только её файлы (список из отчёта части или по `git status` с фильтром),
  потому что помощники правят записи параллельно; общий `tools/check.py` перед коммитом — ошибок 0.
- Сетевые обрывы помощников (EPROTO) — продолжать через SendMessage, они продолжают с места остановки.

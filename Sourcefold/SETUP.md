# Sourcefold Setup

This file records reproducible Sourcefold development-tool setup. Update it
whenever a tool, runtime dependency, lockfile, or setup command changes.

## Environment Change Rule

When installing or changing project tooling:

1. Update the relevant project documentation and this setup file.
2. Record what changed.
3. Record why it is needed.
4. Record how to reproduce it on another machine.
5. Keep generated runtime folders such as `node_modules/` out of Git.

## Node Dev Tools

What:

- Sourcefold has a private Node dev-tool package:
  `package.json` / `package-lock.json`.
- The locked dev dependency is `yaml@2.9.0`.

Why:

- The canonical roadmap is YAML.
- Validation should use a real parser and a reproducible lockfile instead of a
  hand-written parser or browser/CDN state.
- The validator supports documentation checkpoints and commit checks.

Reproduce:

```powershell
npm ci
npm run validate:roadmap
```

Windows wrapper:

```powershell
.\scripts\validate_roadmap.ps1
```

Local-only:

- `node_modules/` is generated by `npm ci` and must not be committed.

## Python checks

The contract and pipeline checks use Python, `pytest`, and, for image-aware
checks, Pillow.

```powershell
python -B -m pytest -p no:cacheprovider
```

Python dependencies do not yet have a project lockfile. Discover a suitable
local or Codex-bundled Python and verify that `pytest` and Pillow are present.
A passing development suite does not establish a production runtime.

## OCR runtime portability

Some bounded probe scripts and historical evidence name
`D:\NRI\.tools\tesseract\tesseract.exe`. Evidence records preserve those paths
as provenance and must not be rewritten. Before a future authorized OCR run,
the active scripts need a separately reviewed runtime-discovery contract; the
standalone import does not claim that OCR is portable or authorized.

## Roadmap viewer

The interactive roadmap viewer is a reader of canonical YAML. It loads
`js-yaml` from jsDelivr and should be served through a local HTTP server rather
than opened as a privileged local file. The package-backed validator above is
the offline canonical validation path; browser rendering is not acceptance
evidence.

## Repository working directory

The standalone Git repository is named `Sorceforge`, while the product remains
`Sourcefold`. Run Node, Python, and PowerShell project commands from the nested
`Sourcefold/` directory so canonical `Sourcefold/...` paths continue to resolve
from the repository root.

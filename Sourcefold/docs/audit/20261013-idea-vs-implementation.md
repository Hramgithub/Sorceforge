# Аудит Sourcefold: идея и реализация

- Дата: 2026-10-13
- База: `Sorceforge` `98c2404`; исходная история и код — `https://github.com/Hramgithub/NRI`, каталог `Sourcefold/` (коммит `22fafc14`).
- Метод: чтение кода, документов и evidence; проверка ключевых утверждений вручную. OCR и скрипты проекта не запускались.

## Вывод

Идея здравая, реализация от неё ушла: проект стал машиной по производству
документов о процессе, а не конвейером книг. Практическую задачу по Viral уже
решил kb_creator.

## Идея

Разделение «восстановить английский текст → перевести → вычитать» с
отдельной приёмкой каждого шага — правильное. Принципы fail-closed,
трассируемость до исходника и сохранение структуры (таблицы, врезки,
статблоки) для книжных НРИ разумны.

## Ключевые проблемы

1. **Круговая проверка.** Принятый текст большинства страниц набран вручную
   прямо в скриптах (`build_page_012_aggressive_batch.py`:
   `extraction_method: manual_from_text_evidence_region`,
   `ocr_executed: False`). Качество OCR измерялось против этого же текста.
   Шаг «reference-guided repair» подставлял эталон вместо OCR
   (`repaired_text = ref_text`).
2. **Нет конвейера.** Нет команды «PDF → текст»; кода рендера PDF в
   репозитории нет. Страница 21 потребовала бы ручного копирования 5–6
   скриптов, координат и текста.
3. **Процесс съел продукт.** Каждая страница — ≈5 стадий, у каждой разрешение,
   два ИИ-ревьюера и человек. Шесть базовых решений (форматы, идентичность,
   якоря…) всё ещё открыты, а Core 0.1 не начат.
4. **Цель уже достигнута в другом проекте.** kb_creator выпустил полный Viral
   RU 2026-09-13 (`kb_creator/inputs/viral/production/`: `MASTER_EN.md`,
   `MASTER_RU.md`, DOCX/PDF/HTML, все 124 страницы).

Реальные ошибки контроль всё же ловил (перепутанный формат координат,
обрезанные кропы P005, попытка выдать подстановку эталона за проверку OCR), но
ловили их автоматические проверки и человеческий взгляд, а не бумажные слои.

## Что ценно

- `page_review_semantic_units.py` — словарь смысловых блоков страницы.
- Проверки кропов: границы, порядок чтения, обрезанный текст.
- `ocr_input_surface_policy.py` — какой кроп пригоден для OCR (урок P017/P018).
- Дисциплина: неизменяемые исходники; различие «измерено / прошло / принято».

## Варианты

1. Заморозить Sourcefold как архив уроков; книги вести через kb_creator,
   перенеся туда 3–4 полезных модуля как проверки.
2. Сделать Sourcefold слоем контроля качества поверх kb_creator: постраничная
   сверка `MASTER_EN` с исходником, структура, полнота.
3. Перезапустить маленьким: одна команда PDF → Markdown, одно человеческое
   «принято» на главу, git-коммиты вместо сотен записей.

Рекомендация: вариант 1 или 2. Сначала ответить, что остаётся нерешённым
после kb_creator; если это доверие к английскому тексту — вариант 2.

## Решение владельца (2026-10-13)

Ветка `main` репозитория `Sorceforge` очищена: оставлены только материалы
аудита и handoff. Старый код Sourcefold и kb_creator хранится в
`https://github.com/Hramgithub/NRI` (каталоги `Sourcefold/` и `kb_creator/`).

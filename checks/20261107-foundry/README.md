## Как правки из Foundry попадут в git и в базу — предложение

Сейчас обратного пути нет: мир берёт копии из модуля, правки остаются в LevelDB мира. Предлагаемый поток:

1. **Правка в Foundry** — в мире, как сейчас.
2. **Мир → git FoundryVTT.** Скрипт (как в `scripts/`, только чтение: копия LevelDB во `/tmp`, чтение,
   удаление копии) выгружает выбранные папки мира в исходники модуля — по JSON на документ, в формате
   `fvtt package unpack` из `@foundryvtt/foundryvtt-cli` (его `extractPack` читает и такую копию). Результат
   коммитится в отдельную ветку модуля (например `foundry-sync`), владелец смотрит diff и сливает в `main`.
   Сборка модуля затем собирает паки из этих JSON (`fvtt package pack`) вместо генерации из карточек
   веб-помощника — иначе следующая сборка вернёт старые тексты.
3. **git FoundryVTT → база знаний.** Инструмент в `pipeline/` Sorceforge читает эти JSON на
   зафиксированном коммите FoundryVTT и готовит предложения записей (`pipeline/integrate/README.md`);
   владелец принимает, записи проходят `tools/check.py`. Числа сверяются с книгой, отличия идут в
   `corrections`.

Вопросы к владельцу — по одному, ответы записываются строкой Р-NN в `docs/project-goal.md` §6.

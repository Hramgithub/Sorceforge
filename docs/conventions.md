# Правила записи данных базы знаний

Единый свод правил для тех, кто создаёт и меняет записи в `kb/` (помощники-агенты и владелец).
Задания помощникам включают этот файл целиком (Р-139). Источник правил — журнал решений
`docs/project-goal.md` §6 (более позднее решение отменяет более раннее), `AGENTS.md` и схемы
`schemas/*.schema.json`; если этот файл с ними расходится, прав журнал, а файл исправляется.
Пометка «(практика)» — правило из сложившихся записей, отдельного решения нет; «(схема)» — из схемы.

## 1. Файлы и формат

- Одна запись — один файл `<slug>.json`; имя файла совпадает с последней частью `id` (практика).
- Формат: UTF-8 без BOM, отступ 2 пробела, переводы строк LF, перевод строки в конце файла — ровно то, что даёт `json.dumps(rec, ensure_ascii=False, indent=2) + "\n"` (кириллица не экранируется) (AGENTS.md, `pipeline/fix/normalize_terms.py`).
- В каждой записи: `schema` (`sourcefold.<kind>.v0`), `id`, `kind`, `name` (`{ru, en}`, `ru` обязателен), `axes`, `sources` (не пустой) и обязательные поля своей схемы (схема).
- `id` общей записи — `coc:<kind>:<slug>` (`coc:creature:abhoth`); записи одной книги — `<book_id>/<kind>/<slug>` (`pobeg-iz-innsmuta-ru/character/abigeyl-marsh`); `kind` в id — в единственном числе (схема).
- `slug` — строчная латиница, цифры и дефис (шаблон `^[a-z0-9-]+([:/][a-z0-9-]+)+$`); из английского названия — по-английски (`22-revolver`), иначе транслитерация русского: `kh`, `zh`, `ts`, `ch`, `sh`, `shch`, `y` (й, ы), `yu`, `ya`, ь и ъ опускаются (`dnevnik-dzheremi-krouforda`) (практика).
- `id` после создания не меняется, даже если запись переименована; прежнее название уходит в `aliases` (Р-40, Р-82). Исключение — сюжетная запись книги, которая встретилась во второй книге: она переезжает в общую папку с id `coc:<kind>:<slug>`, все ссылки на неё переписываются, старый id — в `corrections`; вторая книга дополняет общую запись своим источником, а не заводит свою (как город, Р-80; Р-154).
- Места: `coc:location:<город>-<номер раздела>-<slug>` или `coc:location:<город>-<slug>` (`innsmouth-207-ezotericheskiy-orden-dagona`); карты — `coc:map:<город>-<slug>` (практика).
- `book_id` — `<slug названия>-<язык издания>` (`keeper-rulebook-ru`, `malleus-monstrorum-2-en`, `masks-of-nyarlathotep-en`); каждый записан в `pipeline/source/books.json` — едином списке книг (название, издание, PDF, смещение страниц); новая книга сначала записывается туда, книгу вне списка `tools/check.py` считает ошибкой (Р-148). В `sources` `book_id` может уточнять часть издания (`nabor-khranitelya-pregens-ru` у записей из `kb/books/nabor-khranitelya-ru/`) (практика).
- `axes.era`: по умолчанию `1920s` (Р-04); `any` — не зависит от эпохи; `axes.ruleset`: `core`, `pulp` (Pulp действует при любой эпохе, Р-03), `other`. Запись эпохи или расширения дополняет запись ядра, если она есть, иначе заводится новая (Р-02).

Где лежат записи:

| `kind` | Общие записи | Записи одной книги |
|---|---|---|
| `creature` | `kb/creatures/` | `kb/books/<book_id>/creatures/` — уникальные существа сценария и профили «… («Маски»)» (Р-74, Р-75) |
| `character` | `kb/characters/` | `kb/books/<book_id>/characters/` (Р-78) |
| `tome` | `kb/tomes/` | `kb/books/<book_id>/tomes/` — книги, описанные только в сценарии (Р-131) |
| `skill`, `occupation`, `spell`, `weapon` | `kb/skills/`, `kb/occupations/`, `kb/spells/`, `kb/weapons/` — всегда общий справочник, даже если запись пришла из сценария («Управление судном», «Штык (примкнутый)») | — |
| `location` | `kb/locations/` — город одна запись на все книги (Р-80) | — |
| `map` | `kb/maps/`, картинка — `app/maps/<slug>.jpg|png|webp` (Р-120) | — |
| `item`, `handout`, `organization`, `scene`, `scenario` | `kb/items/`, `kb/organizations/` и т. д. — только то, что встречается в нескольких книгах (Р-154) | `kb/books/<book_id>/items/`, `handouts/`, `organizations/`, `scenes/`, `scenarios/` — всё, что нужно одной книге (Р-128, Р-129, Р-133, Р-134) |

## 2. Источники и приоритет

- Задача — точно извлечь данные из книги и правильно сложить их в базу; анализ смыслов сценария в задачу не входит (Р-05).
- Числа не придумываются: каждое сверяется со страницей книги (с её изображением, если текстовый слой ненадёжен или книга — скан) (handoff, Р-46).
- Порядок по умолчанию: числа — по первоисточнику, русские формулировки — из русского издания или веб-помощника, затем сверка с «Книгой хранителя» (Р-20).
- Существа: Malleus Monstrorum 7e важнее «Книги хранителя» (Р-22), книга Malleus важнее карточек Malleus Keeper Deck (Р-23); русские формулировки «Книги хранителя» сохраняются, источник Malleus ставится в `sources` первым, каждая замена — в `corrections` (Р-22).
- Заклинания: русская «Книга хранителя» > английская > Grand Grimoire > «Маски Ньярлатхотепа» 7e (для их заклинаний) > веб-помощник; расхождения книг — в `quality.notes` (Р-51, Р-54, schemas/README).
- Книги Мифов: числа — по русской «Книге хранителя»; экземпляры из сценариев — в `copies` (Р-57, Р-65).
- Оружие: числа — таблица XVII русской «Книги хранителя» по изображениям страниц, английская таблица — для названий (Р-58); иные числа сценария справочник не переписывают, а идут в `source_variants` (книга, страница, текст как напечатано) (Р-124); у модели позиции (`model_of`) числа сценария важнее таблицы (Р-105).
- Новые данные другой части книги о персонаже, уже заведённом по первому источнику, его не переписывают: другой статблок — вариант «Во время рейда (с. N)», новые факты — абзац в описании («В рейде: …»), противоречия — `errata` с обеими страницами, значение остаётся по первому источнику (Р-125).
- Источник — оригинал издателя, официальный перевод или перевод, который владелец отметил надёжным; машинный перевод источником не служит никогда, даже как подсказка для чисел. Вид издания записан в `pipeline/source/books.json` (`edition`: `original | official | trusted | machine`, а `other` — не книга: веб-помощник, каталог оружия); читать можно только первые три (Р-147). Новая книга записывается `python pipeline/source/pages.py register`: вид издания — по метке в начале имени файла владельца (`[RU 7e]` — официальный, `[RU-фан 7e]` — надёжный, `[RU-ИИ 7e]` — машинный, `[EN …]` — оригинал; правила — `pipeline/source/library.json`) (Р-149, Р-164).
- Числа — по оригиналу, если он есть; русские формулировки — из надёжного перевода; расхождение чисел перевода с оригиналом — в `errata`. Без оригинала надёжный перевод — полный источник, в том числе для чисел. Наш перевод с оригинала (флаг `translated`) — только если надёжного перевода нет (Р-147, Р-20, Р-21).
- Неполная запись дополняется тем, что есть в книге в другом месте (основная статья, профиль родителя, общая таблица, «Книга хранителя») (Р-41).
- Где книги не хватает, допустим вывод из текста: значение ставится, а в `corrections.reason` (и в `errata.note`, если в книге пропуск) пишется «вывод из текста (Р-41)» (Р-41).
- `sources[]` — по элементу на каждое место книги, откуда взяты данные: `book_id`; `physical_page` — страница PDF; `printed_page` — напечатанный номер; `method`; `verified` — числа сверены с книгой; `entry_page` — физическая страница начала статьи, если она раньше страницы блока (Р-32); `note` — что взято с этой страницы (схема).
- `method`: `book_text` — прочитано и сверено с книгой; `helper_migration` — перенесено из веб-помощника; `mineru` — извлечено MinerU без сверки; `manual` — введено вручную (схема).
- Название сценария или главы, откуда персонаж, — в `sources[].note`, а не в отдельном поле (Р-43).
- Описательный текст и механики — по-русски; если русского источника нет, это наш перевод и флаг `translated`; появится русский источник — перевод заменяется (Р-21, Р-33).
- Переводятся и строки `raw` статблока (броня, скорость, атаки за раунд, шанс и урон, потеря рассудка), пояснения и цитаты способностей; числа и кубы не меняются (Р-33, уточняет Р-21).
- У способности `raw` — текст книги как напечатан (у английских книг — по-английски, это доказательство), русский текст — в `summary`, он обязателен (Р-144; проверяет `tools/check.py`).
- Не переводятся: `name.en`, английские псевдонимы, оригинальные названия заклинаний, имена персонажей (Р-33); имя из английской книги — транслитерацией в `name.ru`, оригинал — в `name.en` (Р-45).

## 3. Изменения, опечатки, качество

- Любое изменение значения существующей записи и любое значение, взятое вместо значения другого источника, — элемент `corrections` (Р-19, Р-22, Р-23, Р-125).
- `corrections[]`: `field` — путь (`statblock.characteristics.STR`, `statblock.attacks[Захват]`, `description.ru`); `from` — прежнее значение (`null` — не было); `to` — новое или его краткое описание; `reason` — почему, с книгой и страницей, путь к сверке — тоже здесь; `ref` — только номер решения, по которому сделано исправление, «Р-NN», или `null`, если решения нет (Р-140; проверяет `tools/check.py`).
- `errata[]` — опечатки и противоречия книги: `field`, `printed`, `expected`, `note`, `fixed`; значение в записи остаётся как напечатано (Р-32).
- Значение исправляется только по правилам ниже; тогда в записи — исправленное, напечатанное — в `errata.printed`, `fixed: true` («исправлено в записи») (Р-35).
- Половина и пятая процента — с округлением вниз (`value // 2`, `value // 5`); неверные исправляются в `half`, `fifth` и в скобках `raw` (Р-35, `pipeline/fix/percent_parts.py`).
- Если неверные половина и пятая точно подходят к другому проценту, верным считается напечатанный процент, доли исправляются, возможная опечатка в проценте — в `errata.note` (Р-77); сам процент меняется только решением владельца (5 случаев Р-35).
- Производные значения персонажа проверяет `tools/check.py` (`tools/derived.py`); ПЗ с округлением вверх и Скорость без возрастной поправки — приёмы книг, не опечатки; другие расхождения — в `errata` как напечатано (Р-161).
- Несходящиеся числа существа (бросок, среднее, ПЗ, БкУ, Комплекция) исправляются по большинству: меняется число, расходящееся с двумя согласованными; без большинства — как напечатано и вопрос владельцу (Р-36).
- Расходятся только бросок и среднее — среднее пересчитывается по броску; неясные случаи — как напечатано с пометкой в `errata` (Р-37).
- Таблица против текста статьи: если текст однозначно объясняет механику — берётся текст, иначе таблица; другое — в пометке (Р-38).
- Явно задуманное книгой (исполинский размер) остаётся как напечатано, несходимость — в `errata` (Р-76).
- В `errata` только важное ведущему: числа, правила, механики, названия атак, ссылки не туда, два разных значения (Р-39).
- Словесные опечатки английского текста, исчезнувшие при переводе, не записываются; мелкое оформление исправляется молча: «05» → «5», «70%%» → «70%», запятая вместо косой черты, пропущенные скобки и знаки (Р-39).
- `quality.notes` — только пометки о наших данных: источник, расхождения книг и таблиц, перевод, чего нет в справочнике, что выведено; внешность, где встречается, правила и сюжетные факты — в `description` или `legend` (Р-62).

| Флаг `quality.flags` | Значение |
|---|---|
| `translated` | «перевод»: русский текст — наш перевод с английского (Р-21) |
| `parse_uncertain` | «опечатка книги»: стоит ровно у записей с непустым `errata`, в любом виде записей (Р-141; ставит `pipeline/fix/errata_flag.py`, проверяет `tools/check.py`) |
| `incomplete` | «неполно»: в книге нет части данных (schemas/README) |
| `editorial_text` | текст от редакции, не из книги: придуманное имя (Р-67), каталог 1920-х (Р-58), фраза об аналоге навыка (Р-123) |
| `ocr_suspect` | распознавание сомнительно (схема; сейчас не используется) |
| `quality.needs_review: true` | не флаг, а поле: запись ждёт решения владельца (схема) |

## 4. Написание

- Кубы — латинская строчная `d`: `1d6`, `1d100`, `+6d6`, `(2d6+6)×5`, везде, в том числе в `raw`, таблицах и текстах; не «1D6» и не «1к6»; умножение — `×`; соотношения вроде «1 к 1» — не кубы (Р-27, `pipeline/fix/normalize_dice.py`).
- Обозначения характеристик — как в русской «Книге хранителя» (Р-27, schemas/README, `pipeline/fix/normalize_terms.py`):

| Ключ JSON | Пишем | Не пишем |
|---|---|---|
| `STR` | СИЛ | — |
| `CON` | ВЫН | — |
| `SIZ` | ТЕЛ | РАЗ, ВЕЛ |
| `DEX` | ЛВК | ЛОВ |
| `APP` | НАР | — |
| `INT` | ИНТ | — |
| `POW` | МОЩ | — |
| `EDU` | ОБР | — |
| `hp` | ПЗ | ОЗ |
| `mp` | ПМ | — |
| `damage_bonus` | БкУ | — |
| `build` | Комплекция | — |
| `move` | Скорость | СКО, MOV |
| `sanity`, `sanity_loss` | Рассудок, «потеря Рассудка» | РАС, SAN |
| `luck` | Удача | — |

- Рассудок, Скорость, Комплекция и Удача в наших текстах пишутся словами; сокращения «РАС», «СКО» — только в `raw` и других цитатах как напечатано (Р-146; проверяет `tools/check.py`).

- Английские сокращения (STR, HP, DB, SAN) в русском тексте не пишутся: только ключи JSON и цитаты английского текста в пометках о расхождениях изданий (практика, Р-64).
- Числа статблока: `raw` — как напечатано (доказательство), `value` — разобранное число; бросок характеристики — в `roll` как в книге (`3d6×5`, `(2d6+6)×5`) и остаётся на виду, у видов с средними значениями `averages: true` (Р-34, схема).
- Процент: `raw` как в книге `50% (25/10)`, `value`, `half`, `fifth` (Р-35, схема).
- Ведущий ноль («05%», «00%») остаётся как напечатано в `raw`, в базах навыков и упоминаниях базового шанса («базовый навык 05%»), в бросках по таблицам d100 («01–20»); в остальном нашем тексте проценты без ведущего нуля («снижаются до 5%»). «05» → «5» по Р-39 — только мелкое оформление наших текстов и списка опечаток (Р-153).
- Урон: `raw` как в книге, `dice` — кубы без БкУ, `adds_db` — прибавляется ли БкУ (схема).
- Меры в текстах — метрические, как в русской «Книге хранителя»: ярд → метр 1 к 1 (игровая условность книги), фут → метры (÷3, округлённо), миля → км (×1,6), фунт → кг/г, унция → г, дюйм → см, галлон → л (Р-64).
- Если книга даёт обе меры («1 миля / 1,6 км»), остаётся метрическая; не меняются английские названия и обозначения калибров (.38, «5-дюймовое орудие» как название) и цитаты английского текста в пометках (Р-64). Старые меры допустимы только в наших пометках о данных (`quality.notes`, `errata[].note`, `corrections[].reason`), в `caliber` и в `source_variants` (текст сценария как напечатан); везде остальном их ловит `tools/check.py` (Р-142).
- Оружие называется «Тип «Марка» модель» по-русски (`Пистолет «Кольт» Вудсмен`), модели каталога тоже переводятся; прежнее русское название — в `aliases`, английское — в `name.en` (Р-63).
- Калибр — поле `caliber` у всего огнестрельного оружия и артиллерии; недостающий в книге — из общеизвестных данных с пометкой «справочно, не из книги (Р-63)» в `quality.notes`; у холодного, метательного и взрывчатки калибра нет: в данных `caliber` — `null`, «—» показывает просмотрщик (Р-63, Р-145).
- Заклинание: `name.ru` — по русской «Книге хранителя», веб-помощнику или наш перевод, `name.en` — оригинал (по нему ссылаются карточки) (Р-33, Р-51); народное — «(народное)» / «(Folk)» в названии (Р-66).
- `aliases` — другие названия из книг и переводов как напечатаны; остаются, даже если совпадают с названием другой записи (Р-96, Р-97, Р-100).
- Своих псевдонимов, повторяющих название другой самостоятельной записи того же вида, не добавлять (у «Льва» нет «Тигра»); исключения — разновидность с именем общего вида («Ми-го») и настоящий титул божества (Р-95).
- Другой перевод того же термина — псевдоним существующей записи, а не новая запись (Р-49, Р-81, Р-96).
- Дом называется «Дом …» / «Хижина …» (другое здание — по своему виду: «Склад Бэбсонов»), а не именем жителя; имён людей («Семья …») в псевдонимах зданий нет, старое название — только в `corrections` (Р-82, Р-143).
- Каждый безымянный персонаж (готовый сыщик или персонаж Хранителя, которого книга обозначает только ролью: «Агент Бюро», «Патрульный») получает придуманное имя по эпохе, стране и месту действия: флаг `editorial_text`, книжное обозначение — в `aliases`, в `quality.notes` — «имя придумано (Р-150), в книге — …» (Р-67, Р-150).
- Групповой профиль и типаж (одна запись на нескольких человек) не получает одного имени, а получает `names` — 4–6 готовых придуманных имён по эпохе, стране и месту действия, флаг `editorial_text` (Р-151).
- Слово «архетип» не используется: типовой персонаж — `stock_type` («типаж») (Р-26).
- Типографика (практика): кавычки «…», внутри „…“; тире « — » с пробелами; диапазоны «–» без пробелов (`с. 104–105`, `1–8`); страница в тексте — «с. N» (печатная); десятичная запятая (`1,6 км`); разряды через пробел (`1 750`); буква «ё»; многоточие «…».
- Перечисление пишется в абзаце через «;» — просмотрщик сам покажет его списком (Р-138). Если книга сама печатает список по пунктам, каждый пункт — абзац, начинающийся с «•»; номера оставляются, только если это номера книги (отсеки на карте, порядок целей). Звёздочек, дефисов и своей нумерации в начале строк нет, данные под показ не переформатируются (Р-138, Р-152; проверяет `tools/check.py`).
- Тексты раздаточных материалов для игроков (`handout.text`) — как напечатаны в книге (Р-138).
- Картинки — поле `images`: ужатые копии в `app/art/<вид>s/` через `pipeline/art/add_images.py`, в `source` — откуда оригинал; раздатку, сделанную владельцем, подписывать «раздатка владельца» (Р-165).

## 5. Виды записей

- Существо: `category` — `animal | mythos_monster | mythos_deity | avatar | supernatural`, `subcategory` — как в источнике (Р-18, Р-103); у аватара подкатегория называет божество так же, как связь `avatar_of` («аватар Ньярлатхотепа») (Р-108).
- Разделы Malleus: Powers → `abilities`, Magic → `statblock.spells`, пояснения к атакам → `attacks[].notes`, Aura → `aura`, Encounters → `encounters`, Cult → `cult`, Possible Blessings → `blessings` (Р-28, Р-29).
- Описание существа — краткое, не полный текст книги; история и культ — в `legend` (Р-18).
- Группы людей — персонажи, а не существа (Р-84); особь — персонаж, если она член человеческой семьи со своей историей, и существо, если это безымянное чудовище (Р-94).
- Профиль известного вида из сценария: у записи без статблока он берётся из сценария с источником; если числа другие — отдельная запись «<Название> («Маски»)» в папке книги со связью `instance_of` на вид; совпадающие профили не дублируются (Р-75, Р-79).
- Персонаж: `roles` (`npc`, `pregen`) — подсказка, а не ограничение (Р-26); групповой профиль (таблица на несколько человек) — одна запись со `stock_type` и `variants` (`label` + `statblock`) (Р-74).
- Персонажа без статблока заводят обычной записью персонажа (житель, «Зловещие зацепки», упомянутые мимоходом) (Р-78, Р-128).
- Роль в сценарии — в `legend` (Р-43); `background` — «Характер и окружение» (Р-44), `background.secret` — тайна для Хранителя (Р-45); биография — в `legend` (Р-44).
- `occupation` — как в источнике, `occupation_ref` — запись справочника профессий (Р-46); разные профессии «Книги сыщика» не объединяются (Р-61).
- Навыки в статблоке: `name` — как напечатано, `skill` — ссылка на справочник, `specialization` — отдельно, `value` — как в книге (Р-25, Р-48).
- Навык существа, которого нет в правилах для сыщиков, — запись справочника категории «навыки существ», `base.raw` «—», одна на английский термин Malleus (`name.en`), русские варианты — в `aliases` (Р-48, Р-49).
- Навык сценария без механики (книга не даёт правил и не просит бросать) записи не получает и остаётся текстом в статблоке (Р-126); навык со своей механикой — своя запись, близкий навык — в `see_also` (Р-123).
- У навыка — контрнавыки `opposed_by` (навык или характеристика `coc:characteristic:pow`, пояснение, страница) (Р-47).
- Заклинание: `category` — один из 14 типов: Атака, Проклятие, Связь, Вызов и изгнание, Призыв и укрощение, Контроль и разум, Защита, Зачарование, Врата и путешествия, Создание существ, Изменение тела, Познание, Природа и стихии, Исцеление (Р-66, `pipeline/fix/spell_types.py`).
- `mechanic`: «мгновенное» (ресурс разом — эффект сразу), «поддерживаемое» (ресурс тратится на поддержку), «ритуал» (ресурс долго тратится ради эффекта); связь с божествами и существами — ритуал (Р-69).
- Держится сосредоточением без дальнейших трат — «мгновенное» (Р-70); длительность покупается по частям — «поддерживаемое» (Р-71); порог ритуала — сотворение около 10 минут и дольше или обряд (Р-72).
- `cost.raw` — как в книге, плюс разбор (`magic_points`, `sanity`, `pow`, `other`); `description` — полный пересказ механики; `deeper_magic` — глубинная магия (Р-52).
- `variant_of` — семейство заклинания; вариант стоит в том же типе, что и семейство, если действует так же (Р-52, Р-106).
- Кто знает заклинание, хранится один раз — в `statblock.spells.items` (название как напечатано + ссылка `spell`); заклинателей в `refs` заклинания не пишут, `refs` — кого заклинание призывает, подчиняет, с кем связывает (Р-52, Р-109).
- Книга Мифов: каждое издание — отдельная запись, `edition_of` ведёт на общую запись книги (Р-56); `spells` — как напечатано в списке книги + ссылка (Р-57); `copies` — экземпляры из сценариев (Р-65); люди и существа из истории книги — в `refs` (Р-112).
- Оружие: атака статблока ссылается на оружие полем `attacks[].weapon` (Р-59); `model_of` — только оружие того же рода и того же навыка, что позиция таблицы (Р-104, Р-105).
- Из каталога 1920-х хранится только механика, которой нет в книгах Chaosium; опыт вне боя (редкие патроны, законность, аксессуары без правил) не хранится (Р-98).
- Место: `location_type` — `город | район | здание | место | область`; `part_of` — где находится (место → район → город, у города `null`) (Р-78).
- `number` — номер раздела по путеводителю/карте книги, `address` — почтовый адрес; это разные системы (Р-125, схема).
- `residents` — только те, кто живёт там сейчас по тексту книги; бывшие, умершие, исчезнувшие, гости, похороненные, изображённые и упомянутые — в `refs`, их история — в описании (Р-82, Р-101).
- Вид существа — житель, если живёт там постоянно; где он только проходит или бывает по зову — в `refs` (Р-102).
- Зона (река и т. п.) — запись места с `along`: места на ней и вдоль неё с `note`; сами места остаются в своих районах (Р-135).
- Таблицы-вводные — `tables[]`: `title`, `kind` (`слухи | встречи | события | зацепки | прочее`), `dice`, `intro`, `rows[{roll, text, refs}]`, `source` (Р-78).
- Город — одна запись на все книги: другие книги добавляют к нему места, таблицы и истории со своим источником (Р-80); Й’ха-нтлеи — самостоятельный город, связан с Иннсмутом через `refs` (Р-80).
- Карта: метки `spots[]` в процентах от картинки, `target` — место или другая карта; `printed: false` — вычисленная метка, которой на карте нет; `text` — пояснение буквы в одной записи; `note` — сомнение по метке; того, чего нет в книге (контуры районов), не рисуем (Р-120).
- Сюжет: `item` (артефакт, улика, вещь: где найти, что даёт, у кого), `handout` (текст для игроков), `organization` (цели, члены, где базируется), `scene` (когда, где, участники, проверки, исход) (Р-128).
- Сцена: `arc.scenario` — сценарий или этап, `arc.part` — часть как в книге, `arc.order` — порядок по страницам; сцена пересказывается полно, чтобы по ней можно было играть (Р-133, Р-134).
- Сценарий: `summary`, `keeper_info`, `hook`, `advice`, `steps[{title, text, optional, refs}]` со ссылками на сцены, места, людей и раздаточные материалы, `conclusion`; этап (цель рейда) — тоже запись `scenario` с `part_of` на свой сценарий и `order` (Р-133, Р-134).
- Если книга не печатает текст раздаточного материала дословно, в `text` — её пересказ, пометка — в `quality.notes` (Р-130).
- Место сюжетной записи — `found_at`, `based_at`, `where`; по ним она попадает в гайд города (Р-132). Если книга не связывает место и событие прямо, сцена остаётся на общем месте, а возможное место получает ссылку на сцену и фразу «возможно, здесь…» как вывод из текста (Р-41, Р-156).
- Таблица правил с броском — запись вида `table` (`kb/tables/`, `coc:table:<slug>`): `category`, `dice`, `description` (вступление), `rows[{roll, title, text, refs}]`, `notes`; строка таблицы (одна фобия, одна мания) — не отдельная запись; текст и числа — по странице русской «Книги хранителя», подсказки веб-помощника, которых нет в книге, не берутся; название из других изданий и Foundry — в `aliases` (Р-171).
- Правило — запись вида `rule` (`kb/rules/`, `coc:rule:<slug>`), одна тема на запись: `category`, `summary` (суть), `text` (правило полностью), `steps` (порядок действий из текста книги), `tables[{title, columns, rows, note}]` (таблицы без броска; таблица с броском — запись `table` в `refs`), `examples` (примеры игры из книги), `refs`; текст и числа — по странице русской «Книги хранителя»; журналы Foundry и веб-помощник — подсказка, их добавок, которых нет в книге, не берём (Р-175). Одна запись — один раздел книги (заголовок раздела внутри главы), мелкие подразделы — внутри записи; `optional: true` — необязательное правило книги; `id` — `coc:rule:<slug>` по английскому названию раздела (Р-177).

## 6. Связи

- `relations[]`: `{type, target, note, note_back}`; связь хранится в одной записи, обратную сторону показывает просмотрщик (Р-30).
- Связи и ссылки ставятся только между записями базы; упомянутые без записи остаются текстом; несуществующую цель не придумываем — кандидатов в новые записи перечисляем в отчёте (Р-30, Р-42).
- `note` — кем цель приходится этой записи, `note_back` — кем эта запись приходится цели (видно в карточке цели) (Р-42, Р-118).

| `type` | Когда |
|---|---|
| `form_of` | настоящая форма или разновидность того же существа (Возлюбленный Ктулху, гибрид с акулой) (Р-30, Р-79) |
| `instance_of` | особь вида или боец по групповому профилю: для игры берётся статблок цели; без `note`, пояснение — в `note_back`, если не повторяет название вида (Р-79, Р-92, Р-122) |
| `avatar_of` | бесспорный аватар божества; «по мнению некоторых» — `related_to` (Р-30, Р-86) |
| `spawn_of` | потомство, личинки, созданные или превращённые; как именно — в `note` (Р-116) |
| `servitor_of` | служит божеству или существу (Р-30, Р-42) |
| `transforms_into` | превращается в другое; стадия развития связана с поздней формой только им, без `form_of` (Р-115) |
| `relative_of` | родственник, кем приходится — в `note` / `note_back` (Р-42) |
| `knows` | знакомый, друг, коллега; учёба и сообщничество — тоже `knows` (Р-42, Р-91) |
| `works_for` | только работа или подчинение; питомцы и стражи человека — тоже (Р-82, Р-91) |
| `rival_of` | недруг, соперник; родство и соперничество — две разные связи (Р-42, Р-90) |
| `variant_of` | тот же преген в другом варианте (Р-42) |
| `related_to` | книга сама сомневается или приводит другую версию («по одной из версий», «спорно», «другие отрицают»); единственная или преобладающая версия («по преданию», «по мнению большинства») — своим типом (Р-83, Р-89) |

- Симметричные связи (`relative_of`, `knows`, `rival_of`) хранятся один раз, в одной из двух карточек, с `note` и `note_back`; вторую копию не заводить (Р-114, Р-118).
- Совпадение имён у персонажей разных книг — не связь и не дубль: обе записи остаются (Р-99).
- Другие поля-ссылки (схема): `same_as` — та же запись в другой книге; `model_of` (оружие), `variant_of` (заклинание), `edition_of` (книга), `see_also` (навык), `occupation_ref`, `attacks[].weapon`, `skills[].skill`, `spells.items[].spell`, `abilities[].refs`, `refs`, `residents`, `along`, `part_of`, `arc.scenario`, `found_at`, `held_by`, `based_at`, `members`, `where`, `participants`, `leads_to`, `steps[].refs`, `tables[].rows[].refs`, `spots[].target`.
- Сюжетные записи связаны ссылками с персонажами, местами, книгами Мифов и заклинаниями; обратную сторону показывает просмотрщик, в карточку цели её не пишут (Р-128, Р-129).
- Таблица сценария, нужная и вне него, хранится у города или места, а в `tables` сценария на её месте — `{"from": "<id записи>", "title": "<title таблицы точно как в той записи>"}`; таблицы, нужные только в сценарии, остаются в нём (Р-136).

## 7. Полнота

- Материал книги не отбрасывается по своему усмотрению: если неясно, куда его деть, он сохраняется таблицей или текстом у ближайшей записи, а вопрос — в отчёт; переносит потом владелец (handoff, правило «не отбрасывать без вопроса»).
- Каждая таблица книги попадает в `tables` записи (места, сценария) или в другую запись; ни одна не теряется (Р-78, Р-119, Р-136).
- Сознательно не взятое (мелочи без механики или без текста в книге) перечисляется в разделе «Не взято» в `checks/<дата>-<тема>/README.md` (Р-119, Р-130, Р-131).
- Сомнения, требующие правки существующих записей, — технический долг в той же папке сверки; сами записи не правятся (Р-119).
- Сценарий собирается так, чтобы провести его по базе без книги; приёмка — каждый заголовок раздела книги находится в базе: таблица «Заголовок книги | Страница | Где в базе» в `checks/<дата>-<сценарий>-playable.md` (Р-134).
- Недостающее для игры (места, сцены) дописывается, сцены пересказываются полно (Р-134).

## 8. Работа помощника

- Помощник пишет только назначенные ему файлы; остальные записи (справочники, город, чужие записи) не трогает.
- Правки общих записей — только предложениями в формате `pipeline/integrate/README.md` (Р-139).
- Свои файлы проверяет `python tools/check.py <файлы>`: ошибок должно быть 0, предупреждения — разобрать (Р-139, AGENTS.md).
- Страницы книги читает `python pipeline/source/pages.py show|grep|image <book_id> …` (Р-139).
- Python запускается как `python -I -B` (handoff).
- Не коммитит, не собирает просмотрщик и не запускает массовые исправления по всей базе (`pipeline/fix/*.py` без списка файлов): массовые правки — только по указанным файлам (Р-139, AGENTS.md).
- В отчёте: созданные и изменённые файлы, предложения правок общих записей, «Не взято», кандидаты в новые записи, новые `book_id`, вопросы владельцу.
